## Architecture Findings

# 기술 아키텍처 리뷰 메모: BLOKS 서비스

## 1. 현황 분석

### 홈페이지 배포 아키텍처
- **현재 아키텍처**: BLOKS 서비스의 홈페이지는 전통적인 모놀리식 아키텍처로 운영되고 있으며, AWS EC2 인스턴스에서 호스팅되고 있음.
- **서비스 특징**: AI 기반의 가상 오피스와 분석 대시보드 등 실시간 협업 기능이 포함되어 있어, 성능과 사용자 경험이 매우 중요함.
- **트래픽 패턴**: 주말 및 특정 이벤트 시 트래픽 증가 예상.

## 2. 목표
- BLOKS 서비스 홈페이지의 성능을 최적화하여 사용자 경험을 향상시키고, 안정적인 트래픽 처리를 보장한다.
- SEO 최적화를 통해 검색 엔진에서의 가시성을 높이고, 타겟 사용자(스타트업, 개발팀)에 대한 접근성을 증가시킨다.

## 3. 실행 방안

### 3.1 배포 아키텍처
- **정적 사이트 생성기**: Vercel 또는 Netlify를 사용하여 정적 웹사이트를 배포. 이는 빠른 로딩 속도와 안정적인 성능을 제공.
- **CDN 전략**: 
  - Cloudflare 또는 AWS CloudFront를 사용하여 정적 자산을 전 세계적으로 캐싱. 이를 통해 사용자에게 더 빠른 로딩 시간 제공.
  - 이미지 및 비디오 콘텐츠는 최적화하여 전송 크기를 최소화.

### 3.2 SEO 최적화
- **메타 태그**: 
  - 적절한 메타 태그를 추가하여 검색 엔진에서의 가시성을 높인다.
  - Open Graph(OG) 태그 설정으로 소셜 미디어 공유 시 시각적인 매력을 증가시킨다.
- **키워드 최적화**: 타겟 사용자 관련 키워드를 분석하고, 홈페이지 콘텐츠에 적절히 포함하여 검색 엔진 최적화 강화.

### 3.3 성능 최적화 (Core Web Vitals)
- **LCP (Largest Contentful Paint)**: 초기 로딩 속도를 최적화하기 위해 이미지와 CSS를 최적화하고, 필요한 자원만 로드.
- **FID (First Input Delay)**: 클릭 가능한 요소의 반응성을 높이기 위해 자바스크립트의 크기를 줄이고 비동기 로딩을 활용.
- **CLS (Cumulative Layout Shift)**: 페이지 레이아웃의 안정성을 높이기 위해 모든 이미지에 크기를 미리 지정하여 레이아웃 이동을 방지.

## 4. 성과 지표
- **성능 지표**: Core Web Vitals(LCP, FID, CLS) 목표 수치 설정 및 정기적인 모니터링.
- **SEO 성과**: 검색 엔진에서의 순위 변화, 유입 트래픽 분석 및 키워드 성과 모니터링.
- **사용자 경험**: 사용자 피드백 및 분석 도구를 통한 페이지 로딩 시간 및 사용자 상호작용 분석.

이와 같은 실행 방안을 통해 BLOKS 서비스의 홈페이지는 성능을 극대화하고, 사용자 경험을 향상시키며, 타겟 사용자에게 효과적으로 도달할 수 있을 것입니다.
